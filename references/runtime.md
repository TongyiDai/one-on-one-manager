# Agent runtime contract

这份文件面向执行本 Skill 的 Agent。README 负责让人快速理解；`SKILL.md` 负责工作流；本文件负责运行时判断和失败处理。

## Trigger and first step

触发条件包括：用户提到 1:1、一对一、直属下属沟通、管理者辅导、沟通复盘、会前准备、会后纪要、行动回看，或要求基于飞书资料准备谈话。

第一步固定为：确认沟通对象、时间窗口、沟通模式和输出用途，再检查当前飞书用户身份与租户。对象、时间或身份不明确时，先补齐关键条件；不要用全域搜索猜测。

## Runtime and capability checks

执行真实飞书读取前运行：

```bash
lark-cli auth status --json --verify
```

要求当前身份为用户身份且校验通过。随后按需确认 Calendar、Docs/Drive、VC/Note/Minutes、IM、Task、OKR 等领域能力是否可用。不要因为某个领域不可用，就用 bot 数据、其他员工数据或模型推测填补缺口。

本仓库提供两个安全检查：

```bash
scripts/doctor.sh --json
python3 scripts/smoke_test.py
```

`doctor.sh` 只检查本地命令和用户身份状态，不读取员工资料；`smoke_test.py` 只检查 Skill 文件、引用、Scene JSON 和 SVG 结构，不连接飞书。

## Inputs and outputs

最小输入：

- 沟通对象：姓名、open_id 或用户明确提供的可定位身份。
- 时间：日程时间、上次 1:1 时间，或默认近 30 个自然日。
- 模式：会前准备、会后整理、行动跟进或即时辅助。
- 输出用途：管理者私密草稿，或准备与员工共享的内容。

默认输出必须写明：

1. 数据时间范围。
2. 实际读取的数据源。
3. 未覆盖的数据源和原因。
4. 事实、员工已表达、管理者观察、待验证推断、未知。
5. 可执行的 1—3 项行动及负责人、截止时间、完成定义。

## Authentication and tenant boundaries

- 真实读取默认使用 `--as user`。
- 企业飞书与个人飞书保持隔离；不能跨租户拼接上下文。
- 只读取当前用户有权访问、且与本次 1:1 直接相关的资料。
- 不批量读取直属下属以外人员的数据。
- 权限不足时保留“未覆盖”或“未知”，向用户说明可行的授权路径。

## Read/write levels

| 等级 | 默认行为 | 额外条件 |
|---|---|---|
| L0 草稿 | 整理、分析、起草问题和行动 | 默认允许 |
| L1 只读 | 读取日程、共享文档、共同会议、共同消息、任务和 OKR | 当前用户有权访问 |
| L2 写入 | 更新文档、创建任务、修改妙记、发送消息 | 用户明确授权；写后回读 |

L2 的“用户明确授权”需要包含动作和目标，例如“把这份纪要写入指定文档”或“创建一个分配给我的任务”。“帮我整理一下”只授权 L0/L1。

## Default data window and evidence rules

- 默认近 30 天；低于双周频率时，可扩展到 60—90 天并在输出中说明。
- 会议只纳入双方共同参加且与当前工作目标有关的场次；标题不能直接当作结论。
- 消息只纳入双方共同参与的 P2P 或群组线程，优先承诺、反馈、阻塞、决策和行动，并读取必要 thread 上下文。
- 文档只纳入共同编辑、明确共享、被双方在当前项目中引用或直接关联任务的文档。
- 对方单独浏览或拥有的文档不作为默认输入；浏览行为不构成工作表现证据。
- 原始逐字稿和可定位原文优先于自动总结；自动总结只能作为索引。

## Fallbacks and failure states

| 情况 | Agent 行为 |
|---|---|
| 没有日程 | 输出“未找到相关日程”，继续处理用户提供的材料或明确授权的文档 |
| 只有会议标题 | 只记录会议发生，不推断会议结论 |
| 无法访问妙记/文档 | 标记“未覆盖”，提供会中补证问题 |
| 消息搜索未授权 | 不扩展搜索，提示用户提供关键词、线程或授权范围 |
| 数据来源冲突 | 并列保留冲突，转成会中澄清问题 |
| 发现敏感信息 | 停止扩展读取，最小化输出并建议人工升级 |
| 写入失败 | 保留草稿，明确“未写入”或“提交但未完成回读” |

## Verification and compatibility

- 本地结构：`python3 scripts/smoke_test.py`。
- Skill 格式：使用宿主提供的 `quick_validate.py`，直到返回 `Skill is valid!`。
- 飞书身份：`lark-cli auth status --json --verify`。
- 飞书写入：服务端确认字段和实际读回共同证明完成；单次提交不能当作完成。
- 兼容性：依赖当前宿主已安装的 `lark-cli` 和领域 Skill；CLI 参数、租户能力和可见资源随版本与权限变化，执行时读取当前领域 Skill，不猜参数。

## Privacy and non-goals

本 Skill 只改善沟通和行动闭环。它不生成员工排名、绩效等级、晋升推荐、调薪建议、淘汰建议、离职预警、心理状态或忠诚度标签；不把管理者私密观察写成员工已知事实；不把 1:1 材料扩展成背景调查。
