# 飞书路由与最小权限

本 Skill 只负责编排 1:1 工作流，底层飞书操作交给现有领域 Skill。调用前先读取对应 Skill 的当前说明和必要 reference，不要猜测 CLI 参数。

| 目标 | 路由 | 读取范围 |
|---|---|---|
| 找即将发生的 1:1 日程 | `lark-calendar` | 指定日期、对象或关键词的日程 |
| 读取共享 1:1 文档 | `lark-doc` | 已知 URL/token，或用户明确授权的文档 |
| 找近 30 日共同会议与妙记 | `lark-vc` → `lark-note` / `lark-minutes` | 双方共同参与、指定时间和工作主题；优先原始逐字稿 |
| 读取/创建正式任务 | `lark-task` | 与本次沟通相关的任务；写入前确认 |
| 读取目标或 OKR | `lark-okr` | 仅当前沟通涉及的周期和对象 |
| 搜索近 30 日共同消息 | `lark-im` | 双方共同参与的 P2P 或群组线程，限定关键词、对象和时间 |
| 读取共同工作文档 | `lark-doc` / `lark-drive` | 双方共同编辑、明确共享或与当前项目直接相关且当前用户有权访问的文档 |
| 发消息 | `lark-im` | 仅用户明确确认后 |

## 身份与租户

- 读取用户个人日程、私有文档、历史会议和聊天时默认使用 `--as user`。
- 开始真实飞书读取前，执行 `lark-cli auth status --json --verify`，确认 `identity=user` 且 `verified=true`。
- 企业飞书与个人飞书必须分开；不能拿 bot 数据填充用户数据缺口。
- 权限不足时只报告缺失范围和可行的授权路径；不要自动申请妙记或文档权限。

## 数据优先级

1. 用户当前明确提供的材料。
2. 共享 1:1 文档中的双方共识与行动。
3. 原始逐字稿、消息和文档中的可定位事实。
4. 平台自动总结只能做索引，用户要求提炼时回到原始内容。
5. 推断只作为待验证问题，不作为事实写入。

## 近 30 日协作上下文规则

- 默认时间窗为最近 30 个自然日；必须在输出首行写明起止日期。
- 会议只纳入双方共同参加且与当前工作目标相关的会议。若只能拿到会议标题，不能把标题当作会议结论。
- 消息只纳入双方共同参与的对话或群组线程；优先读取带有明确承诺、反馈、阻塞、决策和行动的信息，并继续读取相关 thread 上下文。
- 文档优先纳入共同编辑、明确共享、被双方在当前项目中引用或直接关联任务的文档。员工单独拥有、单独浏览或个人空间中的文档不因“与员工相关”自动纳入。
- 读取结果按 `来源｜日期｜主题｜事实｜与 1:1 的关系｜置信度` 形成证据表；未读取到的数据源必须标为“未覆盖”。
- 发现健康、家庭、薪酬、投诉、纪律、医疗或其他敏感信息时停止扩展读取，保留最小必要信息并提示升级路径。

## 写入门禁

- 文档写入：用户明确说“写入/更新/保存到文档”。
- 任务写入：用户明确说“创建任务/加入我的任务/分配给某人”。
- 妙记写入：用户明确指定某条妙记并要求修改。
- 消息发送：用户明确确认发送对象和正文。
- 任何写入都要返回服务端确认结果；没有实际回读或确认字段时，标注为“已提交但未完成回读”。
